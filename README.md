# Багануур Сэтгэлийн Илгээмж — Full-stack жишээ төсөл

Цэцэг, бэлгийн онлайн дэлгүүрийн **backend (Node.js/Express API)** болон
**frontend (React + Vite)** хосолсон төсөл, **QPay** төлбөрийн холболттой.

## Бүтэц

```
astra-flowers/
├── backend/          Express REST API
│   ├── server.js
│   ├── routes/        products, categories, cart, orders
│   └── data/          JSON-based "мэдээллийн сан" (products.json, categories.json)
└── frontend/          React + Vite сайт
    ├── src/components/  Header, Hero, ProductCard, Footer, PetalMark
    ├── src/pages/       Home, Shop, ProductDetail, Cart, Checkout, OrderSuccess
    └── src/context/     CartContext (сагсны төлөв)
```

## Боломжууд

**Дэлгүүрийн тал**
- Ангилалаар шүүсэн бүтээгдэхүүний жагсаалт (Бүх цэцэг, Баяр хургэх, Хайраа илэрхийлэх, Хайрт ээждээ, Surprise барих, Төрсөн өдрийн, Хүндэтгэл илэрхийлэх, Дагалдах)
- Нэрээр/тайлбараар хайх
- Бүтээгдэхүүний дэлгэрэнгүй хуудас
- Сагс (нэмэх/тоо өөрчлөх/устгах) — сервер талд хадгалагдана
**Захиалга ба төлбөр**
- Захиалга өгөх (нэр, утас, хаяг, хүргэх огноо) → order үүсгэнэ
- **QPay төлбөр**: захиалга өгмөгц QR код бүхий төлбөрийн хуудас руу шилждэг
  - Мерчант эрх (`QPAY_CLIENT_ID`/`QPAY_CLIENT_SECRET`/`QPAY_INVOICE_CODE`) тохируулаагүй бол автоматаар **DEMO горим**-оор ажиллана: жинхэнэ QR-ийн оронд "Төлбөр хийгдсэн гэж тэмдэглэх (demo)" товч гарч ирнэ — үүгээр бүтэн урсгалыг (захиалга → төлбөр → баталгаажуулалт) турших боломжтой
  - Жинхэнэ мерчант эрхээ `backend/.env`-т бичихэд код өөрчлөлтгүйгээр шууд бодит QPay рүү шилжинэ
- REST API бүхэлдээ JSON, frontend-ээс Vite proxy-гоор дуудагдана

**Админы тал** (`/admin`)
- Нууц үгээр нэвтрэх (`ADMIN_PASSWORD`, анхны утга: `astra2026`)
- Хянах самбар: нийт бараа, захиалга, орлого, бага нөөцтэй бараанууд
- Бараа удирдах: нэмэх / засах / устгах (ангилал, үнэ, хямдралтай үнэ, нөөц, зураг, тайлбар, онцлох эсэх)
- **Ангилал удирдах**: нэмэх / нэр засах / устгах (ашиглагдаж буй ангиллыг устгахаас хамгаалдаг, "Бүх цэцэг" устгагдахгүй)
- Захиалга удирдах: жагсаалт, дэлгэрэнгүй харах, статус солих (хүлээгдэж буй → баталгаажсан → хүргэгдэж буй → хүргэгдсэн / цуцлагдсан)
  - Бүтэн CRUD: шинэ захиалга гараар үүсгэх, хэрэглэгч/бараа мэдээллийг засах, устгах
  - Баганаар эрэмбэлэх (дугаар, хэрэглэгч, дүн, огноо, төлбөр, статус — толгой дээр дарж)
  - Он, сараар шүүх
  - **Excel рүү экспорт** хийх (`.xlsx`, идэвхтэй шүүлт/эрэмбэлэлтийн дагуу)

## Ажиллуулах заавар

### 1. Backend (port 5000)

```bash
cd backend
npm install
npm start
```

API туршилт: `http://localhost:5000/api/health`

### 2. Frontend (port 5173)

Шинэ terminal нээгээд:

```bash
cd frontend
npm install
npm run dev
```

Хөтчөөр нээх: `http://localhost:5173`
Админ панел: `http://localhost:5173/admin` (нууц үг: `astra2026`, эсвэл `backend/.env` дотор `ADMIN_PASSWORD`-оор өөрчилнө)

> `vite.config.js` дотор `/api` хүсэлтүүдийг автоматаар `localhost:5000` руу proxy хийдэг тул CORS асуудал гарахгүй.

### 3. Production build

```bash
cd frontend
npm run build
npm run preview
```

## QPay тохируулах (заавал биш)

Одоогоор `backend/.env` файл байхгүй бол сервер **DEMO горим**-оор ажиллаж, төлбөрийг дуурайлган турших боломжтой.

Жинхэнэ QPay холбохын тулд:

1. `backend/.env.example`-г хуулж `backend/.env` нэрээр хадгал
2. QPay-ийн мерчант дашбоардаас авсан утгуудыг бөглө:
   ```
   QPAY_CLIENT_ID=...
   QPAY_CLIENT_SECRET=...
   QPAY_INVOICE_CODE=...
   QPAY_CALLBACK_URL=https://таны-домэйн.mn/api/payments/qpay/callback
   ```
3. Backend-ээ дахин асаа (`npm start`) — өөр ямар ч кодонд өөрчлөлт хийх шаардлагагүй, автоматаар бодит QPay руу шилжинэ.

> `QPAY_CALLBACK_URL` нь интернэтээс хүрэх боломжтой публик URL байх ёстой тул локал хөгжүүлэлтэд `ngrok` зэрэг tunnel ашиглана уу.


## Дараагийн алхмууд (санал)

- `data/*.json` файлын оронд бодит мэдээллийн сан (PostgreSQL/MongoDB) ашиглах
- Admin-ий нэвтрэлтийг hashed нууц үг + жинхэнэ session/JWT болгож бэхжүүлэх (одоогийн байдлаар demo зорилготой энгийн token)
- Төлбөрийн систем (QPay, Sansar Payment гэх мэт) холбох
- Хэрэглэгчийн бүртгэл/нэвтрэлт (энгийн хэрэглэгчийн тал) нэмэх
